## SQL 多表查询与订单统计

Python 后端通常将 SQL 查询结果映射为接口响应。LEFT JOIN 用于保留左表全部行，
即使右表没有匹配记录也返回左表记录。只统计已付款订单时，可以把付款条件放在
JOIN 的 ON 条件中；若在 WHERE 中要求右表 status='paid'，没有匹配订单的客户会丢失。
COUNT(右表主键) 忽略 NULL；COUNT(*) 可能把没有匹配订单的左表占位行也算进去。
SUM 在没有有效数值时返回 NULL，可用 COALESCE(SUM(金额), 0) 返回零。
金额可存整数分以避免浮点误差。GROUP BY 必须对应需要分组的实体。

## FastAPI 输入与身份校验

使用 Pydantic 模型验证字段、长度和枚举；不要直接相信浏览器上传的 user_id。
用户身份应从公共 current_user 依赖获取，读取业务记录时同时限制记录 ID 和 user_id。
写操作复用公共 require_csrf。401 表示尚未登录；403 可以表示来源或 CSRF 校验失败。
跨用户记录查询返回统一的 404，避免泄露其他用户是否存在某条记录。

## Python 同步与异步

async def 并不自动把阻塞操作变为非阻塞。同步数据库驱动和耗时计算不能直接阻塞
异步事件循环。同步路由可以由框架在线程池执行；较长任务也可交给独立执行服务。
超时后应区分客户端停止等待和后端任务是否真正取消，保留可恢复的任务记录。

## 数据库事务与重复提交

需要一起成功的多次写入使用同一个事务，失败时回滚。并发分配 attempt_no 时，
必须配合任务级锁或事务和唯一约束，不能只在 Python 中先查最大值再直接插入。
幂等请求使用稳定 request_id；同一个编号与相同内容重试返回原结果，编号复用为
不同内容时返回冲突。长时间执行 SQL 校验期间不要一直占用业务数据库事务锁。

## 确定性测试与能力证据

SQL 答案通过服务端准备的多组数据比较，覆盖空表、没有关联行、零金额和状态筛选。
若题目没有要求排序，比较应保留重复行数量而忽略行顺序；列顺序按题目要求检查。
服务故障、超时和执行限制不等同于学员答错。证据关联题目版本、提交编号、规则版本
和验证时间。通过一道题只证明该任务通过，不直接断言已经掌握整项技能。
