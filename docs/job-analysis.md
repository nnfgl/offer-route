# 岗位分析与调度入口

## 已实现的操作

注册登录→工作台“开始岗位分析”→粘贴原文或填入示例→分析→核对原文→从最近分析恢复。
必需条件、加分项和未明确优先级的要求分组呈现。空结果提示补充材料，失败保留可查询记录。
每位用户只可查看自己的记录。其他账户查询同一任务 ID 返回 404。

本地规则仅处理明确词句；保留“或/且”等组合条件，混合必需和优先条件的句子标为待确认。
否定和不限类句子暂不提取；遇到不熟悉的标题、复杂否定或超长条件，可能漏提，需要核对原文。
有原文依据只表示引用可核验，不保证所有语义分类正确，也不代表用户已经满足这些要求。

## 公共模型客户端

`core/model_client.py` 提供 `DeepSeekClient.complete_json(system, content, validate)`。
调用者提供验证回调；岗位模块先验证 Pydantic 结构，再检查 quote 是原文连续子串。
无效 JSON、空白、截断、虚构引用、429、服务端错误可在总时限和预算内有限重试。
401/402/403/其他不可重试状态立即失败，不将上游响应正文或密钥写入错误。
请求不执行招聘正文中的指令，不开放外部工具；密钥不出后端。

配置参考 `.env.example`；OFFER_MODEL_OUTPUT_BUDGET 是每次任务预留的最坏输出 token 数，
不是人民币限额。默认单次 1800、总预留 3600，最多 2 次，总时限 12 秒。
服务端未返回用量的失败请求可能仍有账单成本，展示用量只包括已报告的计数。

## 后续成员如何接入

1. 后端从当前登录身份取得 user_id，通过 task_id + user_id 查询岗位分析结果，禁止跨用户读取。
2. 检查任务 status=completed，取 result.data.requirements 和 result.evidence 作为诊断输入。
3. 将候选人材料与岗位要求通过共享 AgentRequest/AgentResult 协议传递。
4. 为新 Agent 建立自己的路由、数据结构与页面；提交归属、CSRF、失败路径测试。
5. 完成真实业务后再更新调度器阶段；当前三个后续阶段明确为 skipped，不模拟完成。

公共 AgentResult 未修改。岗位结果额外携带 requirement id、priority、category、quote、
source_start/end/line；偏移按 Unicode 码点计数。
任务 payload 保存结构化结果与 trace，摘要列表最多返回最近 20 条。
记录由请求同步生成，当前没有后台队列或自动重试入口；失败后用户可重新提交生成新任务。

## 验证

按 README 执行 pytest、前端构建和 Playwright。模型测试全部使用 MockTransport，
覆盖虚构引用、401、429、500、空白 JSON、错误结构、预算和总超时，不消耗付费 API。
浏览器测试覆盖桌面/手机分析、引用高亮、历史恢复及材料不足提示。
生产上线和多实例任务队列仍不属于本里程碑。
