# 四人分工与开发顺序

## 里程碑 0：公共基础（本次）

仓库结构、环境配置、账号注册登录、Cookie 会话、工作台、Agent 协议、CI。
完成测试后，以此版本作为四人共同开发起点。

## 里程碑 1：按业务拆分

| 成员 | 主责 | 主要路径 | 首个可验收结果 |
| --- | --- | --- | --- |
| A（组长） | 岗位分析 + 流程调度 | agents/job、agents/orchestration | 输入招聘要求，输出必需/加分技能及原文证据 |
| B | 简历与能力诊断 | agents/diagnosis | 输入模拟简历及岗位要求，输出有依据的优势和待验证项 |
| C | 实战训练与验证 | agents/training | 为一个薄弱点生成任务，并用受限工具检查结果 |
| D | 文字与语音模拟面试、复盘 | agents/interview | 支持打字或语音回答、问题朗读，共享追问与复盘流程，回写待训练项 |

每个人同时完成自己对应的前端页面、API 和测试。共享页面任务单独认领，
不把全部前端工作交给 D；A 管理依赖与合并节奏，不包揽集成修复。

## 首批 Issue 草案

1. `[公共] 用户能力档案与任务记录迁移`：登录用户只可访问自己的记录，含越权测试。
2. `[岗位] 招聘要求结构化提取`：手动粘贴要求即可工作，每项要求保留原文依据。
3. `[诊断] 简历信息与能力证据关联`：使用模拟数据，区分自述、作品支持、任务验证。
4. `[训练] SQL 练习与确定性校验`：在独立受限环境运行，含超时和失败路径。
5. `[面试] 文字与语音面试会话及复盘`：支持文字输入、录音转写及问题朗读，两种模式共享有限轮次追问和评分依据；权限被拒或语音服务失败时可回到文字输入。
6. `[调度] 单岗位完整路线`：诊断→训练→面试→更新档案，含重试上限和费用记录。

建议先支持 Python 后端岗位、文字与按轮次进行的语音面试和一类练习。
成员 D 的详细范围与验收条件见 [文字与语音面试](interview.md)。接入 DeepSeek 的公共客户端
统一负责后端密钥、超时、重试、结构化输出与用量统计，禁止各模块重复实现。

## 合并要求

main 保持可启动；分支按 Issue 创建，PR 至少由一位同伴审查，CI 通过再合并。
共享协议变化先在 Issue 说明。首轮各自用固定结构化输入开发，再按真实接口联调。
