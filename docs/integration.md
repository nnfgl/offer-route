# 四模块整合与验收

2026-11-04 整合 PR #8（训练）、#9（诊断）、#10（面试），沿用已有账号和岗位分析。

2026-11-05 新增统一求职路线、岗位能力档案、面试后练习及持久化语音复盘队列。

## 统一运行

按根目录 README 安装基础依赖，后端使用 `app.main:app`，前端使用 Vite。
日常开发无需 MySQL、Chroma 服务或外部模型；每个组员保留自己的 `.env`、虚拟环境和数据库。
不要把训练实验入口作为全项目入口，也不要运行模拟数据种子覆盖已有记录。

1. 注册或登录，选择“开始求职路线”，填入岗位要求与简历，可直接使用示例。
2. 路线依次分析岗位、诊断简历并为首个可练习的 SQL 缺口出题。历史路线可恢复每步进度。
3. 在路线中完成 SQL 校验，再进入关联面试。没有适用 SQL 缺口时可直接进入面试。
4. 关联面试的复盘建议自动生成待练习项。用户可保存改写后的回答，档案同时保留原复盘和逐字证据。
5. 语音需配置百炼和 DeepSeek。配置步骤及真实设备验收见 [语音文档](voice-interview.md)。

每个自动步骤最多运行两次，公共模型客户端限制单次运行的超时和输出预算。
已知模型用量累积到路线，云端费用以供应商账单为准。覆盖计数仅统计已通过 SQL 校验的必需要求。

规则诊断可能将自述移入待验证项；当前训练入口只消费明确的 SQL 缺口。
如果没有这类缺口，页面会说明原因，不会伪造训练任务。

## 合并修复

- 同时注册岗位、诊断、训练和文字/语音面试路由，工作台开放四个入口。
- 新增训练页面；训练服务复用主应用鉴权、CSRF、所属用户及统一 SQLite。
- 从 B 的已存诊断映射 C 的训练输入：要求 ID 和原文绑定，逐字核对岗位引用。
- 默认训练资料来自包内合成示例，使用确定性测试向量，明确标为 synthetic；
  不是经过质量验证的语义检索。原 Chroma/MySQL 实验适配器保留在可选入口。
- 诊断优势必须有证据和类型，要求 ID 不能套用另一要求的文字；规则证据信号限定同一句。
- 诊断复用一次公共模型客户端调用，全部重试共用总超时与 token 预算。
- YAML 提示词、训练 SQL 和示例资料被包含在安装包中。

## 数据库升级

统一迁移为 v1 账号会话 → v2 岗位 → v3 简历诊断 → v4 训练和面试 → v5 求职路线与复盘练习 → v6 语音复盘队列。
不重写已应用的 v1/v2/v3。v4 建立训练和公共面试表，并保留独立面试兼容存储。
已有 D 分支 v2/v3 实验库按表结构识别，补齐缺少的公共表并保留原记录。
迁移检测和 DDL 在同一事务中执行；失败时回滚，不靠删库或手改版本解决冲突。
高于当前版本或缺少关键字段的库会明确停止升级。

启动前可自行备份开发数据库。不要向已有库执行 `database-schema.sql`，它是隔离评审参考。
后续数据库增量由组长统一从 v7 编号。MySQL 实验库由独立适配器管理。

## 验证方式与边界

完整后端回归需额外安装 `backend/requirements.training-local.txt`，包含 Chroma 测试依赖。
MySQL 测试需显式启用并提供独立测试服务，默认跳过，不代表 MySQL 已验证。

- 后端：账号安全、数据归属、模型预算与证据、SQL 校验与幂等提交、面试状态与语音供应商模拟。
- 集成：同一账号从岗位到诊断、SQL 错误/正确答案、训练证据、关联面试及服务重启恢复。
- 升级：已有账号、岗位、诊断、旧文字和语音实验数据库，重复升级与失败回滚。
- 浏览器：桌面和手机上的账号、岗位、诊断、训练、文字面试和模拟语音交互。
- 安装包：实际构建 wheel，检查提示词、SQL 和示例资料可读取。

真实 DeepSeek 请求、真实麦克风、中文云识别/播放和插话延迟需要密钥及人工验收；
自动测试使用供应商模拟，不代表已完成真实云服务验收。
本版本按单进程 SQLite 运行，包含可恢复的语音复盘队列。多实例托管还需共享数据库与限流方案。
